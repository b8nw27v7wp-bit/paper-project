# 项目总计划书 - 智能学习任务规划与管理系统

> 题目：基于多智能体协作与记忆增强的自进化学习任务规划与管理系统 — 融合MCP工具链与多模态感知的知识驱动架构
> 周期：6-7个月 / 28周 | 版本：v0.1_20260822

## 1. 项目目标

解决传统学习计划静态、通用、无反馈问题，实现可感知-可规划-可执行-可反思的闭环Agent，支撑论文创新与答辩演示。

## 2. 范围与交付物

- 交付：Electron桌面App + Web端（同Vue代码）+ CLI Trace工具
- 后端：FastAPI单后端，支撑6大创新
- 文档：开题报告 + 设计文档 + 论文 + 双对比实验报告
- 部署：Docker Compose一键启动 + 桌面安装包

## 3. 里程碑

| 里程碑 | 时间 | 交付物 | 验收标准 |
|--------|------|--------|----------|

## 4. 28周详细排期

### P0 1-8周 地基
- W1-2: Monorepo(pnpm+turbo) + Electron IPC + FastAPI /health + Docker(postgres/neo4j/redis) + Naive UI引入
- W3-6: learning_goal/task CRUD + SQLModel(Alembic) + 甘特图/日历增删改
- W7-8: 接DeepSeek-V3，实现Planner单Agent周计划生成，SSE流式返回

### P1 9-16周 核心做深
- W9-11: LangGraph StateGraph(Planner/Executor/Critic/Mentor) + agent_run_log落库
- W12-13: pgvector memory_chunk(1536) + 记忆摘要/召回 + 有/无记忆对比实验设计
- W14-16: PDF切片Embedding + Neo4j三元组抽取 + PREREQ依赖查询，实现证据式规划

### P2 17-22周 三端与工具
- W17-18: Electron electron-builder配置 + externalBin带FastAPI sidecar + better-sqlite3存窗口状态 + 托盘/通知
- W19-20: MCP Python SDK接calendar-mcp/better-todo-mcp + Qwen-VL多模态拍照识课表 + Typer CLI trace
- W21: APScheduler周日23:00触发Reflector，生成reflection_report并重写下周约束

### P3 23-26周 评估与打磨
- W22-23: 双实验：多Agent vs 单Agent(盲评合理性)、有记忆 vs 无记忆(7日完成率)
- W24: ECharts大屏(完成率/拖延率/图谱) + 性能优化(懒加载/缓存)
- W25-26: E2E测试(Playwright/pytest) + Bug修复

### P4 27-28周 论文答辩
- 论文撰写(8章) + 查重 + PPT + 3分钟演示视频

## 5. 人力与风险

- 单人全栈，P0-P1为关键路径，P2可裁剪MCP为1个、多模态仅做拍照
- 风险1: better-sqlite3/node-pty编译失败 -> 预案: 降级为electron-store/lowdb，node-pty删除
- 风险2: 模型费用 -> 统一DeepSeek-V3，限流Redis
- 风险3: Neo4j内存高 -> 开发用Docker限2G，数据量<1万节点
