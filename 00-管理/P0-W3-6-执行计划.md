## 2. 约束与策略

- 栈锁定：不新增超文档依赖；SQLModel + SQLite `apps/server/data/app.db` 兜底，`DATABASE_URL` 为 PG 时自动切换
- 认证：W3-6 不做 JWT，`user_id` 依赖注入（`get_current_user_id`，X-User-Id 兼容），为 Auth 留扩展点
- 时间：ISO8601 UTC，`deadline>now+1d`、`planned_end>planned_start`（tasks.py:24）
- 分页：page>=1、size 1-100 默认 20，返回 `{items,total,page,size}`

实际处置结果：

| 原风险 | 实际处置 |
|---|---|
| SQLite vs PG 差异 | JSON 字段（citations）TEXT 存取；切 PG 仅改 DATABASE_URL，代码零改动 |
| FullCalendar 拖拽校验失败 | 前端回滚 + message 提示，PUT 40001 不落脏数据 |
| 无 Docker 时 PG/Redis 未起 | SQLite 兜底建表，Goal/Task 链路不受影响 |

## 4. 设计（按实际实现）

- 模型（映射 04-DB §2.2）：`LearningGoal(user_id,title200,deadline,status active/archived)`；`Task(goal_id FK,title200,planned_start/end,priority1-5,status todo/doing/done/delayed,source_agent,citations)`；`TaskExecutionLog(task_id FK,actual_duration0-600,completion_rate0-1,delay_reason)`
- 校验位置：与原计划差异 — 未全放 SQLModel Field，而是集中在路由层显式校验（deadline/时间倒置/status 枚举/标题空），错误码统一 40001/40401
- complete 语义增强：completion_rate>=1 置 done，<0.5 置 delayed 并自动补 delay_reason（tasks.py:110-116）——原计划只写 log 不回写任务状态
- 删除语义：Goal 删除级联删 tasks（goals.py:107-111）；Task 删除级联删 execution log（tasks.py:179-181），非 DB 层 CASCADE 而是应用层显式删除
- 分页实现：`select(func.count()).select_from(q.subquery())` 单查询计数，无 N+1（goals.py:58、tasks.py:56）
