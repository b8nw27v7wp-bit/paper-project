# P0 W3-6 执行计划 — 目标/任务闭环 + 日历

> 版本: v0.1_20260822 | 阶段: P0 W3-6 地基核心 | 前置: P0-W1-2已验收 (Monorepo+Docker+Health+Vue+Electron) | 依据: 02-需求与设计 01需求F01/F03 + 04数据库 + 05API

## 1. 目标与验收

**目标**: 打通 Goal→Task→打卡 业务闭环，日历/甘特可增删改，为 W7-8 单Agent 生成做数据底座。

**验收** (逐条可测):
- [ ] `POST /api/v1/goals` 校验 title 1-200 必填、deadline>now+1d，成功201；`GET /goals?status&pag` 分页20；`GET /goals/{id}` 含 tasks；`PUT/DELETE` 生效
- [ ] `GET /api/v1/tasks?goal_id&status&page` 列表；`PUT /tasks/{id}` 改时间/优先级/状态；`POST /tasks/{id}/complete` 写 execution_log (0-600, 0-1)；`POST /tasks/batch` 批量；`DELETE` 204
- [ ] 前端：`/goals` 列表+新建/编辑/归档弹窗；`/calendar` FullCalendar 日/周视图，拖拽改期回写 `PUT /tasks/{id}`；任务抽屉可打卡
- [ ] 异常：标题空/截止非法→40001；时间倒置→40001；外键不存在→40401；均不阻断其他链路
- [ ] 性能：单请求<300ms (本地SQLite)，分页正确

## 2. 约束与策略

- **栈锁定**：不新增超文档依赖；DB用 SQLModel + SQLite 文件 `apps/server/data/app.db` (Fallback)，`DATABASE_URL` 为 PG 时自动切 pgvector，满足本地无 Docker 也可验；后续切 PG 零改动
- **认证**：W3-6暂不做JWT，固定 `user_id=1` 注入（`X-User-Id` 可选），为后续 Auth 留扩展点
- **时间**：ISO8601 UTC，校验 `deadline > now+1d`、`planned_end > planned_start`
- **分页**：`page 1..` `size 1-100` 默认20，返回 `{items, total}`

## 4. 后端设计

### 4.1 模型 (映射 04-DB §2.2)

- `User(id, username unique, password_hash, major, learning_style, created_at)`
- `LearningGoal(id, user_id FK, title 200, description 2000, deadline, status active/archived, created_at)` + index(user_id,status)
- `Task(id, goal_id FK CASCADE, title 200, planned_start, planned_end, priority 1-5, status todo/doing/done/delayed, source_agent 32, citations JSON, created_at)` + index(goal_id,status)
- `TaskExecutionLog(id, task_id FK CASCADE, actual_duration 0-600, completion_rate 0-1, delay_reason, created_at)`

校验在 Pydantic/SQLModel Field 上实现，索引在 `__table_args__` 或 `create_all` 后建。

### 4.2 DB 会话

- `app/core/database.py`: `engine = create_engine(DATABASE_URL -> sqlite fallback)`, `get_session()` generator, `init_db()` `SQLModel.metadata.create_all`
- `app/main.py` lifespan 调用 `init_db()`，含 `data/` 目录自动创建

### 4.3 接口 (映射 05-API §3.2/3.4)

- `POST /api/v1/goals` → 201；`GET /api/v1/goals`；`GET /api/v1/goals/{id}` (含 tasks)；`PUT /api/v1/goals/{id}`；`DELETE /api/v1/goals/{id}`
- `GET /api/v1/tasks` (filter goal_id/status, pag)；`PUT /api/v1/tasks/{id}`；`POST /api/v1/tasks/{id}/complete`；`POST /api/v1/tasks/batch`；`DELETE /api/v1/tasks/{id}`
- 统一返回 `{code,msg,data}`，40001/40401 按约定，500走全局 handler

### 4.4 校验要点

- Goal: `deadline` 需 `> now+1day` (UTC)，`status in active/archived`
- Task: `planned_end > planned_start`，`priority 1-5`，`status enum`
- complete: `actual_duration 0-600`，`completion_rate 0-1`

## 5. 前端设计

- `api/goals.ts` / `api/tasks.ts` 基于 axios (沿用 `api/health.ts` 实例)
- `GoalsView.vue`: 顶部统计+新建按钮 → Naive UI Modal+Form (title/deadline/subject) → Table 分页 (actions: 查看/编辑/归档/删除)
- `CalendarView.vue`: FullCalendar dayGrid/timeGrid/interaction，events 来自 `GET /tasks`，`eventDrop/eventResize` → `PUT /tasks/{id}`，点击事件→ TaskDrawer 打卡 (actual_duration/completion_rate)
- `TaskDrawer.vue`: 状态流转 todo→doing→done/delayed，提交 `POST /tasks/{id}/complete`
- 路由: `/` (Home), `/health`, `/goals`, `/calendar`

## 6. 风险与预案

- SQLite vs PG 差异: JSON字段存为 TEXT(JSON dumps)，读取时处理；后续切 PG 改 `DATABASE_URL` 即可
- FullCalendar 拖拽校验失败 → 前端回滚 + `message.error`
- 无 Docker 时 PG/Redis 未起 → 后端 degraded 不影响 Goal/Task
