## 2. 约束与策略

- 栈锁定：仅用 openai 兼容 SDK（`app/core/llm.py` UnifiedClient，provider 无关 deepseek/qwen/openai），SSE 用 sse-starlette
- 降级：LLM Key 为空/超时15s/JSON解析失败重试1次 → mock 兜底，演示不断（planner.py:170-194、generate_plan planner.py:250）
- 数据：`user_id=1` 注入，Task batch 写入，citations 暂空
- 日志：内存 `plan_store` + 落库 `agent_run_log` 双写，SSE 重放三级回退（Redis cache → plan_store 内存 → DB 重建）
- 限流：内存 deque 10/min（plans 路径 5/min，Redis 占位优先）— 证据：app/core/ratelimit.py:10-11、ratelimit.py:53

实际处置结果：

| 原风险 | 实际处置 |
|---|---|
| SSE 跨域/代理 | Vite 同源代理 `/api`→8000，EventSource 相对路径，未遇跨域问题 |
| LLM Key 缺失 | mock 兜底常态化（pytest 环境直接短路走 mock，planner.py:160） |
| SQLite JSON | TEXT + json 存取，稳定无阻塞 |

## 4. 设计（按实际实现）

- Planner：SYSTEM_PROMPT 严格 JSON 数组输出（planner.py:92-113），约束时长相等/不重叠/每日≤hours_per_day/按 deadline 倒排
- mock_generate：deadline 均摊，最长 14 天（与原计划"7天×1-2任务"差异：2026-09 起按需求放宽至 14 天，每天 1-2 任务按 hours>3 分档，planner.py:130-137）
- llm_generate：UnifiedClient timeout=15s、fallback=True、max_retries=1，JSON 截取 `[...]` 解析，失败重试 1 次后抛出 → generate_plan 降级 mock（planner.py:158-194、planner.py:258-268）
- generate_plan 思考轨迹：思考1-5 步骤写入 SSE thought 事件（planner.py:253-276）
- SSE：8 事件（thought/tool_call_start/tool_call/tool_call_end/task_created/critic_feedback/mentor_msg/reflector_patch/done 体系），id 递增 + retry:3000 + Last-Event-ID（Header/Query 双兼容）断点续播（plans.py:560-590）
- plan_store：内存 dict + `put(session)` 全量 events 落库 agent_run_log + `get_or_reconstruct` 从 DB 重建（planner.py:12-90）
- 与原计划差异：
  - 事件从原设想的 4 类扩为 8 类（含 tool_call_start/end 对与 critic/reflector 事件）
  - 2026-09-04 增强：stream 所有权鉴权 `_resolve_trace_user`（plans.py:52、plans.py:496-505）、脏时间容错 `_safe_parse_dt`（plans.py:40）、events 全量落库
  - POST /plans 默认走多 Agent（mode=multi），单轨需 `?mode=single`——多Agent 属 W9+ 范围，P0 验收以单轨为准
