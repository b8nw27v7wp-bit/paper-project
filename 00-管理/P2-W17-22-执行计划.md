## 2. 约束与策略（含历史风险处置）

- **桌面**：`electron-builder` sidecar 双探针，`shell:false` 防 shell 注入；退出钩子 kill 进程树
- **存储**：`better-sqlite3` 开 WAL，异常回退 `electron-store`（原 v0.1 已实现，保留）
- **MCP**：`mcp` SDK `stdio`，超时 3s，mock/异常回退 3 个 mock 工具（v0.1 计划 5s 重试1，实际实现为 3s 回退策略，以代码为准）
- **多模态**：单 key（`llm_api_key`）复用——OCR/ASR 共用，无 key 全链 mock 保演示
- **反思**：APScheduler cron 读执行日志算完成率/拖延率，LLM 生成 analysis+patch
- **历史风险处置**：v0.1 风险"sidecar 启动竞态"→ 双探针顺序判定闭环；"无 key 演示断链"→ mock 回退闭环；"跨端数据一致性"→ CLI 全走同一后端 REST 闭环

## 4. 设计（按代码实际实现）

- **Sidecar 启动**（main.ts:161）：生产环境先探 `process.resourcesPath` 下 externalBin 二进制，失败探 extraResources 下 uvicorn 启动脚本；`spawn(..., { shell:false })`；`before-quit` 终止。
- **窗口状态持久化**（main.ts:27-62）：better-sqlite3 建 `window_state` 表（WAL 模式），启动时恢复 bounds，关闭时写入；初始化异常降级 electron-store。
- **MCP 客户端**（client.py:311）：`command!="mock"` 时经 `ClientSession + stdio_client` 真连，超时 3s；`command=="mock"` 或任何异常 → 回退内置 3 个 mock 工具，保证 `/mcp/call` 恒可用。与原计划差异：原计划"calendar/todo 走 stdio"，实际 mock；实测真 stdio 仅 studying-planner（CLI）。
- **多模态**（ocr.py:126 / asr.py:66）：OCR 用智谱 GLM-4V-Flash（OpenAI 兼容视觉接口），返回课程表 JSON，置信<0.6 或异常回退 `_MOCK_COURSES`；ASR 真调 whisper-1，无 key 回退 `_smart_mock_text`。与原计划差异：OCR 引擎为 GLM-4V-Flash 而非 Qwen-VL，文档口径本次已统一。
- **反思调度**（reflector.py:269）：2 个 cron——周日 23:00 `weekly_reflection`、周一 09:00 `weekly_notify`；3 端点 latest/week/run。
- **CLI**（apps/cli/main.py）：Typer+Rich+httpx，12 命令 trace/plan/graph/memory/health/inspector/graph_state/stream（SSE + Last-Event-ID 续播）/plans/planner/agent/project + 无参交互式 chat loop；入口 `studying`（pyproject scripts）。与原计划差异：语言从 Node/Typer-ts 改为 Python，复用后端同栈 httpx。
