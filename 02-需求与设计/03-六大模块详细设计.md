## M1 多智能体协作（P0, LangGraph）— v0.4 加深版 + System Agent 单点

**系统即智能体**：`app/agents/system_agent.py:1` `SystemAgent` 为对外单一智能体，`POST /plans`+`CLI studying`+`MCP studying:plan` 即 `SystemAgent.ainvoke`，内部编排 `6子Agent`，`trace_id` 贯穿。

**目标**：ReAct可追溯的6节点协作规划，论文主创新

**输入**：goal{title,deadline,description,subject}, 记忆Top5, 图谱PREREQ(10), 向量Top10, preferences{hours:1-8}

**State** `app/agents/state.py:1`

```python
class PlanState(TypedDict):
  goal: dict; memory: list; graphDeps: list; vectorDeps: list
  milestones: list; tasks: list; critic_feedback: str; mentor_msg: str
  rewrites: int; trace_id: str; preferences: dict
  _thought: str; _research: dict; _patch: dict
```

**流程（6节点）** `app/agents/graph.py:1`

```
Planner(ReAct thought + mock/LLM, 注入memory/graph/vector, 重写+30min) 
  -> Researcher(显式记忆/图谱/向量计数落tool_calls) 
  -> Executor(透传) 
  -> Critic(规则3项 + LLM二次 + 图谱前置缺失) 
  -> Mentor(读拖延史个性化) 
  -> Reflector(生成patch {reduce_load,add_buffer})
                              |否(重叠/超载/前置) -> Planner重规划(≤2轮)
```

**Prompt** `app/agents/prompts.py:1` 已加深：
- Planner：含 `memoryTop5/graphDeps/vectorHints/critic_feedback`，示例 `hours`，要求 `citations`
- Critic：`{"pass":bool,"feedback":str}` 双校验
- Mentor：20字内结合拖延史

**落库与推送** `app/api/v1/plans.py:1`
- `agent_run_log` 6条 (planner/researcher/executor/critic/mentor/reflector) 全量 `tool_calls`
- SSE 8事件 `thought/tool_call(memory/rag/graph/planner)/task_created/critic_feedback/mentor_msg/reflector_patch/done`，首字节<2s
- 证据式：`Task.citations=[{chunk_id,score}]` 来自 `vectorDeps`
- M7 工作台订阅同SSE并渲染Graph/Inspector

**异常**：LLM超时重试1次；2轮仍驳回返回最佳版+警告+`reflector_patch`

**验收**：Critic拦截率>20%，`pytest test_agents_graph 5 passed`，`35 tests` 全绿

## M2 长期记忆（P0, pgvector）

**双记忆**：短期窗口10轮；长期`memory_chunk(type=memory, embedding vector(1536))`

**写**：任务完成->摘要Prompt("拖延2h因难度高") -> embedding -> 入库

**读**：规划前`cosine>0.75 Top5` -> 注入Planner

**索引**：HNSW `vector_cosine_ops m=16 ef=64`，`user_id+type`联合

**定时**：APScheduler 22:00批量摘要

**验收**：有/无记忆完成率+15%，检索<1s

## M3 RAG+知识图谱（P0, 知识驱动）

**RAG**：PDF切512+overlap50 -> pgvector(type=knowledge) -> Top10检索

**图谱**：LLM抽`(Knowledge)-[PREREQUISITE]->(Knowledge)` -> Neo4j

**流程**

```
上传 -> MinIO -> 切块 -> 入pgvector -> 抽三元组 -> 入Neo4j
规划 -> MATCH PREREQ -> 向量检索 -> Planner证据式生成(带[引用:p3])
```

**可视化**：ECharts Graph，节点按度大小，边为PREREQ

**异常**：抽取失败仅存向量；图谱空走纯RAG

**验收**：100页PDF<60s，召回>70%

## M7 Agent工作台 Chat+Graph+Inspector（P0，新）

**目标**：Chat+Graph+Inspector三位一体凸显智能体与子调用，论文可截图

**输入**：trace_id, SSE流 8事件，agent_run_log 6条，PlanState

**前端**：三栏 `260会话|Chat流|360Inspector`，ChatPanel(气泡+子调用树可折叠+重试)，GraphCanvas(ECharts DAG或vue-flow，节点态pending/running/success/error，边含rewrites回边)，InspectorPanel(JsonViewer+复制)

**流程**：

```
用户prompt -> POST /plans -> 建立trace_id -> SSE订阅 -> Planner首thought -> Researcher并行3工具(tool_call_start/end*3) -> Executor -> Critic双校验 -> (若fail)回边Planner -> Mentor -> Reflector -> done
点击Graph节点 -> 高亮Inspector对应agent_run_log条
```

**状态**：Pinia workbench.ts {traceId,messages[],graph:{nodes,edges},inspector:{state,logs,patch},status}

**SSE契约**：每事件带`id`递增与`retry:3000`，支持`Last-Event-ID`续传，首字节<2s，心跳0.08s

**异常**：SSE断线自动重连；无trace 404；Graph空状态引导

**验收**：6节点渲染<500ms，子调用树展开<100ms，Inspectort与DB一致，导图分辨率≥2x

**关联**：M1(编排) -> M7(可视化) -> 论文图
