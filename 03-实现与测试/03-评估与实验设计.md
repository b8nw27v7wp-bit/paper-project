> 版本：v0.4_20260830 | 03-实现与测试 | 详细版 | 依据 00-项目总计划书 P3 W23-26 + 论文大纲第7章 | 覆盖实验A/B/C + 统计方法 + 追踪说明

## 1. 目标

验证本系统三项核心假设的增益与可观测性，支撑论文第7章“测试与评估”的可复现性与统计可信度：

- H1（协作增益）：多Agent协作（Planner-Executor-Critic-Mentor 6节点StateGraph）相比单Agent直出显著提升计划合理性并降低冲突。
- H2（记忆增益）：记忆增强（pgvector Top5召回+图谱PREREQ）相比无记忆在7日执行中显著提升完成率。
- H3（可观测性增益）：双轨工作台（Chat+Graph+Inspector，SSE 8事件+tracing）相比无工作台（仅日志/接口）显著提升调试效率与问题定位速度，并满足交互性能阈值。

所有实验采用对照/消融设计，报告均值±标准差与独立样本t检验（p<0.05），数据来源为 `agent_run_log` 与 Langfuse 追踪，实验脚本与数据表模板见 §7-§8。

## 3. 实验A 多Agent vs 单Agent（消融，支撑H1）

- **自变量**：规划范式（A组单Agent vs B组多Agent 6节点）。
- **因变量**：
  - 主观：盲评合理性 1-5分（Likert，3人独立盲评，取均值；1=不可执行，5=可直接执行）。
  - 客观：冲突率 = 时间重叠任务对 / 总任务对 ×100%；依赖缺失率 = 缺失PREREQ边 / 应有PREREQ边 ×100%。
- **数据**：20个Goal人工构造，分层覆盖考研/六级/考证各段，含DDL 5-30天、每日可用1-8h、3-5门科目依赖。每个Goal两种范式各生成1次，共40份计划。
- **流程**：
  1. 同一Goal、同一 `preferences{h hours_per_day}` 依次调用 `POST /api/v1/plans`（A组直出，B组走 `multi_graph`）。
  2. 打乱编号后分发3名评分者盲评，计算组内一致性（Krippendorff α，预期>0.7）。
  3. 程序化计算冲突率与依赖缺失率（基于 `task.planned_start/planned_end` 与 `app/graph/neo.py:get_graph` PREREQ校验）。
- **统计**：每组n=20，报告均值±标准差；独立样本t检验（双侧，α=0.05），报告t值与p值；效应量 Cohen's d。
- **预期**：B组合理性 +1.0分（例如 3.2→4.2），冲突率 <10% vs A组>30%，依赖缺失率 <15% vs A组>35%，p<0.05，d>0.8。

## 4. 实验B 有记忆 vs 无记忆（消融，支撑H2）

- **自变量**：记忆供给（A组无记忆 Top0 vs B组有记忆 Top5 + 图谱PREREQ）。
- **因变量**：7日完成率 = 已完成task / 计划task ×100%（主指标）；拖延率 = 逾期完成 / 总完成 ×100%；周调整次数（Reflector改写约束次数）。
- **数据**：1用户7日真实执行log（或高保真模拟：含拖延/偏好/中断，`execution` 表 `duration/rate`），种子 `user_id=1`，初始2 Goal 10 Task，`APScheduler` 周日23:00触发反思。
- **流程**：
  1. 固化7日log后，A组 `asearch_memory` 关闭（`search_memory` mock空），B组开启 `app/services/memory.py:139` 真embedding + 30天衰减 `score*=0.7`。
  2. 各组连续跑7日（每日生成/执行/打卡），`POST /api/v1/plans` 与 `POST /api/v1/tasks/{id}/complete` 循环。
  3. `GET /api/v1/stats/overview?range=7d` 与 `GET /api/v1/stats/trend` 取完成率/拖延率，`reflection_report` 计调整次数。
- **统计**：7日为时间序列，报告日均完成率±SD；对7日完成率做配对t检验（同一用户前后测）或独立t检验（两组并行），p<0.05；同步报告折线图斜率。
- **预期**：B组7日完成率 +15%（例如 62%→77%），拖延率 -12%，调整次数 -20%（记忆减少重复试错），p<0.05。

## 5. 实验C 工作台可观测性（新增，支撑H3）

- **自变量**：可观测条件（A组无工作台：仅 `agent_run_log` + 终端/SSE裸流 vs B组有工作台：`WorkbenchView.vue` 三栏 Chat+Graph+Inspector + `GET /plans/{trace_id}/graph` + `GET /plans/{trace_id}/inspector` + `cache:graph:{trace_id}` 5m）。
- **因变量**：
  - 调试效率：定位时间 T_identify（从异常发生到定位根因节点的时间，秒）；首次定位准确率 = 首次猜中故障节点 / 总故障数；调试轮次（达到修复所需的重跑次数）。
  - 系统性能：Graph渲染耗时（ECharts DAG首帧，阈值<500ms）；Inspector加载（`state/logs/patch` 渲染，阈值<300ms）；SSE首字节时间 TTFB（阈值<2s）；缓存命中率。
- **任务设计**：注入6类可复现故障各2例，共12个调试任务——Prompt缺参、工具超时、Neo4j断连、pgvector召回空、SSE断流、Critic驳回循环。每任务提供 `trace_id` 与故障现象，要求定位到 `AGENT_ORDER` 中具体节点与 `tool_call`。
- **被试**：8-12名开发者（或同一被试交叉设计，平衡顺序效应），随机分A/B组或AB交叉。
- **流程**：
  1. 被试接收故障 `trace_id`，A组仅用 `GET /plans/{trace_id}/logs` 与日志，B组可用完整工作台（Graph高亮 `replan` 回边 + Inspector JsonView + 子调用树）。
  2. 记录 T_identify、准确率、轮次；前端埋点 `performance.now()` 采 Graph/Inspector 渲染耗时，`curl -w %{time_starttransfer}` 采SSE TTFB。
  3. 每任务限时15分钟，超时记为失败。
- **统计**：n=12任务×被试数，报告定位时间均值±SD；独立/配对t检验 p<0.05；性能指标报告 p50/p95 与阈值达标率。
- **预期**：B组定位时间 -40%（例如 420s→250s），首次准确率 +30%（45%→75%），轮次 -35%，Graph p95 <500ms（实测10-107ms），Inspector p95 <300ms，SSE TTFB <2s，p<0.05。

## 6. 统计方法（统一）

- **描述统计**：所有连续指标报告 均值 ± 标准差（Mean ± SD），计数指标报告率与95%置信区间。
- **推断统计**：
  - 两组独立比较：Welch's t检验（不等方差），双侧 α=0.05，报告 t(df)、p值与 Cohen's d（0.2小/0.5中/0.8大）。
  - 时间序列（实验B 7日）：配对t检验或重复测量ANOVA，必要时 Greenhouse-Geisser 校正。
  - 分类准确率：卡方检验或Fisher精确检验。
- **前提校验**：Shapiro-Wilk 正态性 + Levene 方差齐性；不满足时改用 Mann-Whitney U 并报告中位数[IQR]。
- **样本量**：实验A n=20 Goal满足中等效应 d=0.8 时 power≈0.8；实验C 12任务×10被试=120样本点满足调试效率检验。
- **可重复性**：随机种子固定，`trace_id` 贯穿，原始数据与脚本归档于 `data/experiments/`。

## 8. Langfuse追踪与可观测说明

- **贯穿ID**：`trace_id`（UUID）在 `POST /plans` 生成，经 `plan_store` 内存+DB双写（`app/services/planner.py`），贯穿 `multi_graph` 6节点与 `agent_run_log`（含 `trace_id+agent_name` 联合索引 `idx_agent_trace_agent_created`）。
- **SSE链路**：`GET /plans/stream?trace_id=` 返回8类事件（`task_created/plan_update/log/agent_start/agent_end/done/error/heartbeat`），带 `id/retry` 与 `Last-Event-ID` 续传；前端 `stores/workbench.ts` 订阅并回放 `GET /plans/{trace_id}/graph` 与 `/inspector`。
- **缓存**：`cache:workbench/graph:{trace_id}` 与 `cache:graph:{trace_id}` 5分钟TTL，命中时 Graph/Inspector <100ms，未命中时由 `agent_run_log` 聚合重建（`plans.py:_build_graph_from_logs`）。
- **Langfuse集成**：`UnifiedClient` 每次 `chat.completions` 调用记录 `trace_id / agent_name / prompt / completion / latency / tokens / cost`，与 `agent_run_log` 双通道对照；实验时按 `trace_id` 导出 `langfuse trace list --traceId` 校验6节点时序与工具调用树，与 `GET /plans/{trace_id}/inspector {state,logs,patch}` 互证。
- **取证**：实验原始轨迹可通过 `curl /api/v1/plans/{trace_id}/logs` 与 Langfuse UI 按 `trace_id` 检索复核，确保盲评与性能数据可追溯。
